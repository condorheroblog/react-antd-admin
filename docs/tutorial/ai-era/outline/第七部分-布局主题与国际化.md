## 第 22 课 · 布局系统：偏好驱动的多布局架构

### 学习目标

1. 读懂布局目录的组件拆分与组合。
2. 理解五种布局模式如何被同一套偏好状态驱动。
3. 建立"结构组件 / 皮肤排列"分离意识。

### 核心问题

- 布局最容易写成怎样的意大利面条？如何拆分？
- 模式切换时菜单、面包屑、内容区由谁计算？
- 移动端是两套系统还是同一骨架？

### 内容大纲

1. 布局组件树：LayoutRoot → container-layout（KeepAlive+动画）→ sidebar/header/tabbar/footer/content；widgets 全家桶走读。
2. 偏好驱动：use-preferences/use-layout-style/use-layout-menu 映射布局参数；navigationStyle+pageLayout 决定排列；双列混合拆分一级/二级菜单。
3. 移动端：use-device-type 断点 + mobile-menu 抽屉。
4. 菜单计算链路：accordion、展开态、图标、simplebar 滚动。
5. 过渡动画 motion 与 transitionName；iframe/外链布局复用。
6. **横向对比**：自研状态驱动（本项目，可控、可学）vs @ant-design ProLayout（开箱但黑盒、定制深水区）vs vben/pure 式多模板复制。

## 第 23 课 · 主题系统：Design Token、暗色算法与运行时换肤

### 学习目标

1. 理解 Token 三层结构（Seed/Map/Alias）与组件级 Token。
2. 讲清暗色算法生成原理与跟随系统实现。
3. 理解运行时换肤链路与灰色/色弱模式。

### 核心问题

- 暗色为何应"算"出来而非人工配？
- 一个 colorPrimary 如何派生整条色板？
- antd 6 cssVar 让换肤实现发生了什么变化？

### 内容大纲

1. Token 体系：Seed → Map → Alias → Component Token；antd-theme.ts 组织。
2. 暗色算法：default/dark algorithm；切主题即换算法+token 集。
3. 三模式：light/dark/auto（prefers-color-scheme 监听）。
4. 换肤链路：preferences → ConfigProvider → cssVar 运行时变量；hashed:false；Tailwind dark class 同步。
5. 灰色/色弱：html class + CSS filter/变量；版本监控 widget。
6. **横向对比**：antd Token+算法（体系最完整）vs 手工 CSS 变量分层（轻但色板自理）vs Tailwind dark: + next-themes（应用层方案）；组合使用的边界。

- `sequenceDiagram`：点选主题色后的换肤链路。

- 三种主题方案横向对比表。

- 审查清单：是否硬编码颜色绕过 token？暗色下自定义样式是否遗漏？

## 第 24 课 · 国际化架构：i18next 与 antd/dayjs 的三方联动

### 学习目标

1. 读懂 i18next 初始化、资源组织与命名空间。
2. 理解切语言必须同时作用于三套体系。
3. 横向比较 React i18n 主流库。

### 核心问题

- 只翻译业务文案为何不算完成国际化？
- 巨型语言资源如何治理？
- i18n 初始化为何在启动第一步？

### 内容大纲

1. i18next 架构：init 选项、helper 聚合 resources、fallback。
2. 资源组织：按业务域拆 JSON、中英目录对称。
3. 三方联动：react-i18next changeLanguage + antd ConfigProvider locale + dayjs locale + 请求语言头。
4. 缺失键策略：missingKeyHandler 收敛噪音。
5. 切换 UI、偏好持久化、t() 在路由 title 中的使用。
6. **横向对比**：i18next（生态完整、框架无关、插件多）vs react-intl（ICU 标准、API 标准）vs Lingui（编译期、产物小）vs next-intl（绑定 Next）。

## 第 25 课 · 业务组件封装方法论：BasicTable/BasicForm 与 ProComponents 的取舍

### 学习目标

1. 理解"何时封装、何时不封装"判断框架。
2. 读懂 BasicTable/BasicForm/access-control 的抽象边界。
3. 审视 AI 时代封装经济学。

### 核心问题

- 封装收益与成本如何量化？
- ProComponents 有 ProTable，为何还自建 BasicTable？
- AI 秒生 200 行表单，是否消灭封装必要？

### 内容大纲

1. 抽象层次：原生 antd → Basic*（约定收敛）→ ProComponents（重型范式）→ 页面。
2. BasicTable：收敛滚动高度/分页/样式/loading；刻意不接管请求与列定义。
3. BasicForm：form-items 扩展（头像/树）与 antd Form 关系。
4. ProComponents 取舍：用页面骨架级能力、慎用重度 DSL。
5. AI 时代封装决策框架：为"变化点"封装（>3 页面 + 规则会变），不为"重复"封装；红线是不吞类型与可调试性。
6. **横向对比**：纯 antd+AI 直生（直白、可审查）vs Basic*（本项目平衡点）vs ProComponents（最快起步、最深绑定）。

- `flowchart TD`：封装决策树。
- `flowchart LR`：三种方案同一页面的结构层级对照。

### 演示要点（HTML 页规划）

### AI 协作点

- 人：抽象边界（最不可外包的判断）。AI：组件实现。
- 审查清单：封装层是否泄漏细节？类型是否透传？是否解决不存在的问题？

30 分钟。
