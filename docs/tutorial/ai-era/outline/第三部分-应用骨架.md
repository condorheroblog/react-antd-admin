## 第 08 课 · 启动流程设计：异步 setupApp 与初始化顺序

### 学习目标

1. 读懂 [index.tsx](file:///Users/david/i/react-antd-admin/src/index.tsx) 的启动设计。
2. 理解启动函数为何异步、顺序错误导致的具体故障。
3. 建立"启动阶段 / 运行阶段"分层意识。

### 核心问题

- 为何必须先初始化 i18n 再显示 loading？顺序反了会怎样？

4. StrictMode 专题：双渲染暴露副作用的意图；与第三方库/重复请求的摩擦；本项目取舍。
5. 样式入口统一引入位置。
6. **横向对比**：SPA 命令式启动（本项目）vs RR7 Framework Mode / Next 的框架接管启动（SSR/入口黑盒）——为何中后台 SPA 仍选前者。

## 第 09 课 · Provider 分层架构

### 学习目标

1. 读懂 [app.tsx](file:///Users/david/i/react-antd-admin/src/app.tsx) 的 Provider 结构。
2. 理解每层 Provider 注入的能力与嵌套顺序约束。
3. 新增加全局能力时能判断放哪一层。

### 核心问题

- Provider 嵌套的本质（作用域 + 上下文依赖）？
- 为何 StyleProvider 在最外、AntdApp 在最内？
- 如何避免"Provider 地狱"？

### 内容大纲

1. 逐层拆解（外向内）：StyleProvider layer → ConfigProvider（locale/主题算法/Token）→ AntdApp（useApp 上下文）→ JSSThemeProvider → Suspense → RouterProvider。
2. 顺序约束规则：外层能力不依赖内层；同层按数据依赖排列。
3. ConfigProvider 主题对象构造逻辑（细节入第 23 课）。
4. App 层副作用组织：系统主题监听、灰色/色弱 class 切换、语言联动。
5. Provider 聚合封装实践。
6. **横向对比**：Context Provider 组合（本项目）vs 框架内置 DI/插件系统 vs 状态库自带 Provider（Zustand 无 Provider 的差异，呼应第 20 课）。

## 第 10 课 · 三层样式体系：Tailwind + cssinjs + CSS Variables 的共存设计

### 学习目标

1. 理解三套样式机制的职责边界与共存理由。
2. 讲清最大风险（优先级战争）与解法（`@layer`）。
3. 横向比较当前主流样式方案，理解本项目的组合选择。

### 核心问题

- antd 自带 cssinjs 了，为何还要 Tailwind？职责怎么划？
- 多套样式共存，谁覆盖谁谁说了算？
- antd 6 默认 CSS 变量后，覆盖姿势发生了什么变化？

### 内容大纲

1. **纵向演进**：
   - 原生 CSS / Sass·Less 预处理器 → CSS Modules 局部作用域 → CSS-in-JS（styled/emotion）运行时动态 → antd cssinjs（v5）→ cssinjs + 默认 CSS Variables（v6）；
   - 原子化：手写工具类 → Tailwind v3 JIT → Tailwind v4 CSS-first + Oxide；UnoCSS 作为同期方案。
2. 三层样式模型：CSS Variables（组件内部状态变量化）→ cssinjs（主题与局部动态）→ Tailwind（业务页面原子布局）。
3. 职责边界与决策树：外观改 Token/变量，布局用 Tailwind，动态局部用 jss。
4. `@layer` 优先级治理：StyleProvider layer + Tailwind 级联层，取代选择器权重硬刚；`@scope` 新能力。
5. 工程工具：cn（clsx + tailwind-merge）；hashed:false 取舍；styles 目录走读。
6. **横向对比**：Tailwind 4 vs UnoCSS（引擎哲学、生态）vs CSS Modules vs styled-components/emotion；为什么组合是"antd Token/变量 + Tailwind"而不是纯 CSS-in-JS。
