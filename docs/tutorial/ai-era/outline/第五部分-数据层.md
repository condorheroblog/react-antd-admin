## 第 16 课 · HTTP 客户端选型：从 XHR 到 ky

### 学习目标

1. 沿 XHR → axios → fetch → ky 讲清网络请求演进。
2. 理解 ky 设计哲学：fetch 之上的薄封装 + hooks。
3. 横向对比当下主流客户端，给出选型与回退条件。

### 核心问题

- fetch 已普及，为何还需要客户端库？
- axios 拦截器模型与 ky hooks 的本质差异？
- ofetch 等候选什么场景更合适？

### 内容大纲

1. **纵向演进**：XHR 手写回调 → jQuery $.ajax → axios（Promise+拦截器，XHR 底层）→ fetch 原生（Promise+流）→ ky（fetch 薄封装、ESM 优先）。
2. fetch 短板与库价值：超时 AbortSignal、非 2xx 不 reject、JSON 约定、重试、拦截；ky 如何小体积补齐。
3. ky hooks 模型：beforeRequest/afterResponse 数组钩子，基于标准 Request/Response，可组合可测试。
4. **横向对比**：
   - axios：生态最大、上传进度、Node 同构，但体积大、XHR 包袱；
   - ky：轻、fetch 原生心智、浏览器优先（Node 需适配）；
   - ofetch：Nitro 出品、Node/边缘同构更好；
   - redaxios（axios API + fetch）：迁移友好；
   - 选型结论：本项目浏览器 SPA → ky；同构/边缘 → ofetch；存量大项目 → 留 axios。

- `timeline`：请求技术演进。
- `flowchart LR`：拦截器链 vs hooks 数组两种模型对比。

### 演示要点（HTML 页规划）

- 演进时间轴。
- 四大客户端横向对比表（体积/底层/同构/拦截模型）。
- 结论页：原生成熟一寸，封装薄一分。

### AI 协作点

- 人：选型与迁移决策。AI：ky 实例与 hooks 骨架。
- 审查清单：是否照搬 axios 取数心智？是否正确处理 ok 语义？

### 建议时长

25 分钟。

## 第 17 课 · 请求层设计：鉴权注入、错误处理与 token 刷新

### 学习目标

1. 完整读懂请求层横切能力如何在 hooks 中编排。
2. 讲透 401 → refresh → 重放如何避免死循环。
3. 横向对比拦截器式请求层的实现差异。

### 核心问题

- 请求白名单如何设计不漏不滥？
- 刷新接口自身 401 为何死循环？如何打断？
- 业务错误码与 HTTP 状态码在哪一层分流？

### 内容大纲

1. 默认配置：prefix、timeout、retry。
2. beforeRequest：全局进度（ignoreLoading 静默）、白名单、Bearer 注入、语言头。
3. afterResponse：非 ok 分流（401 刷新 / 其余统一错误处理）、成功收尾。
4. 401 刷新专题：无 refreshToken/已在登录页 → goLogin；刷新接口 401 → 立即 goLogin 打断死循环；成功后重放原始 request/options（并发单飞思想）。
5. 错误归一化与类型扩展（ignoreLoading）。
6. **横向对比**：ky hooks 实现 vs axios interceptor 实现同一套能力的结构差异；单飞刷新库（如 axios 生态方案）对照。

- `sequenceDiagram`：并发多个 401 时"一次刷新、全部重放"时序。

- 两种实现模型对照表。
- 白名单/头注入/进度能力卡片。
- 结论页：横切能力集中一次，页面只关心数据。

### AI 协作点

- 人：安全策略与死循环防线。AI：hooks 与刷新逻辑。
- 审查清单：刷新接口是否被误纳入刷新？静默选项是否透传重放？

### 建议时长

30 分钟。

## 第 18 课 · 服务端状态边界：TanStack Query 与 Zustand 的分工

### 学习目标

1. 建立服务端状态 vs 客户端状态分类意识。
2. 理解 Query 心智模型：缓存键、staleTime、后台刷新、失效。
3. 横向对比三大数据获取库。

### 核心问题

- 接口数据塞进全局 store 后为何到处是 loading/同步样板？
- Query 替你管理了什么？v5 API 有何变化？
- 登录态、字典、草稿分别归谁？

### 内容大纲

1. 服务端状态特殊性：异步、共享、会过期、需再同步。
2. 手管服务端状态的七宗罪。
3. Query 心智模型：queryKey/queryFn 与请求层衔接；fresh/stale/fetching 状态机；staleTime/gcTime；focus 刷新、去重、mutations/乐观更新、invalidate。
4. 本项目 QueryClient 配置与 DevTools。
5. 边界示例：用户身份（Zustand，守卫依赖同步读取）vs 列表详情（Query）vs 偏好（Zustand）。
6. **横向对比**：TanStack Query（能力最全、框架无关）vs SWR（轻量、Next 团队）vs RTK Query（Redux 生态绑定）vs GraphQL/Apollo（范式不同）。

- `flowchart TD`："数据归谁管"决策树。

- 结论页：别用客户端状态工具打服务端状态的仗。

- 审查清单：是否 useEffect 手动 refetch？queryKey 是否稳定？

## 第 19 课 · Mock 即契约：vite-plugin-fake-server 与前后端并行

### 学习目标

1. 理解 Mock 定位：提效手段 + 数据契约。
2. 读懂 fake 目录组织与插件配置。
3. 横向对比主流 Mock 方案，理解 enableProd 取舍。

### 核心问题

- 前端写死数组、拦截型 Mock、插件型 Mock 的差别？
- 为何让 Mock 进生产构建（enableProd）？收益与风险？
- 有状态 Mock（登录/路由/通知）如何实现？

### 内容大纲

1. **纵向 + 横向选型**：
   - 纵向：手写写死 → Mock.js 拦截 XHR → Mock 平台/接口工具（Apifox）→ 构建期插件；
   - 横向：vite-plugin-fake-server（同前缀、零切换、随 Vite 一体）vs MSW（Service Worker 拦截、可用于测试/生产级标准）vs Mock.js（不拦 fetch）。
2. 插件工作方式：fake 目录约定、basename /api、延时模拟、切后端零改动。
3. 契约视角：fake 文件即接口形状文档，与 API types 共享。
4. 有状态 Mock：登录态、async-routes、通知未读；faker.js 海量数据。
5. enableProd 取舍：演示站零后端运行；体积与数据假象的控制。

- `flowchart LR`：请求在 Mock 与真实后端间的切换路径。
- `sequenceDiagram`：有状态登录 Mock 的交互。

### 演示要点（HTML 页规划）

- fake 目录 ↔ 业务模块对照。
- 结论页：Mock 的高级形态是可执行契约。

### AI 协作点

- 人：接口契约与数据形状。AI：批量生成 fake 与仿真数据。
- 审查清单：响应类型与 API types 是否一致？是否模拟失败/超时/空数据边界？

### 建议时长

25 分钟。
