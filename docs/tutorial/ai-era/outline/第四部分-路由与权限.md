## 第 11 课 · 路由模式与数据路由 API：RR v5→v6→v7

### 学习目标

1. 讲清 Browser/Hash 的原理、取舍与 basename。
2. 理解三代 API 演变与 Remix 合并带来的数据路由。
3. 横向比较当前 React 三大路由选择。

### 核心问题

- Hash 为什么"丑"但能解决刷新 404？
- v6 嵌套路由 + Outlet 比 v5 Switch 强在哪？
- v7 为何双模式（框架/库）并存？同期 TanStack Router、Next 路由为什么没入选？

### 内容大纲

1. 两种路由模式：History API vs hashchange；刷新 404 成因；basename 与生产子路径；hash 下不可设 basename。
2. **纵向演进**：v5（Switch、useHistory）→ v6（Routes、相对路径、Outlet、对象数组）→ v6.4 数据路由（loader/action）→ v7（Remix 合并，框架/库双模式）。
3. **横向对比**：
   - React Router 7（生态最大、数据路由完整、SPA/SSR 皆可）；
   - TanStack Router（全类型安全、路由即代码，生态较新）；
   - Next App Router（文件路由、绑定 Next/SSR 场景，不适合纯 SPA 模板）；
   - 选型结论与回退条件。
4. 根路由 loader / shouldRevalidate 设计：NProgress 仅在首次进入未加载页启动。
5. 环境变量切换路由模式。

### 图表建议（Mermaid）

- `timeline`：RR 三代 API。
- `flowchart LR`：一次导航从 URL 变化到 loader/渲染的路径。

### 演示要点（HTML 页规划）

- Browser/Hash 取舍表。
- 三大路由横向对比表。
- 根路由 loader 触发时机图。
- 结论页：模式看部署约束，路由看官方主线与类型能力。

### AI 协作点

- 人：模式与 API 路线。AI：生成路由实例。
- 审查清单：是否混用 v5/v6 API？hash 是否误设 basename？

### 建议时长

30 分钟。

## 第 12 课 · 路由组织与元信息类型设计

### 学习目标

1. 理解 core/external/modules 三层分类意图。
2. 掌握 `import.meta.glob` 约定收集与合并机制。
3. 读懂元信息契约：一份配置驱动菜单、标题、权限、缓存。

### 核心问题

- 为什么拆三类路由？
- glob eager 收集比手写 import 数组强在哪、约束是什么？
- handle 元信息该放什么、不该放什么？

### 内容大纲

1. 三层分类：core（login/异常/fallback 永存）、external（免鉴权、不触发用户请求）、modules（业务权限原料）。
2. glob 收集 → mergeRouteModules 展平 → ascending 排序流水线。
3. RouteMeta 字段逐一过堂并标注消费者：title/icon/order、roles/permissions、keepAlive、hideInMenu/currentActiveMenu、iframeLink/externalLink、ignoreAccess/backstage。
4. 路由 id 与路径工具集；菜单由路由单向生成（SSOT）。
5. **横向对比**：集中配置式（本项目）vs 文件约定路由（Next/Nuxt/TanStack）vs 运行时后端下发（第 13 课）；各自对菜单、权限、代码分割的影响。

## 第 13 课 · 动态路由双模式：前端路由 vs 后端路由

### 学习目标

1. 讲透两种权限路由模式的工作方式、优缺点与适用场景。
2. 理解后端菜单数据如何转换为 RR 对象（组件映射难题）。
3. 读懂 access store 如何补丁式写入路由。

### 核心问题

- 前端路由只拿到角色，安全吗？菜单从哪来？
- 后端怎么可能知道前端组件？如何映射？
- 两种模式能同时开吗？冲突如何去重？

### 内容大纲

1. 前端路由模式：路由全在前端，登录后按 roles 过滤；优点与短板（菜单不随后端变、仅体验层）。
2. 后端路由模式：后端菜单树（路径/标题/图标/组件标识）→ 前端页面映射表（glob 注册表）；数据来源两选一（用户信息内嵌 menus / 独立 async-routes 接口）。
3. 模式开关与 Promise.allSettled 并发；双模式同开时的去重。
4. 路由注入：setAccessStore → router.patchRoutes + 菜单/扁平索引同步。
5. replace 重匹配：地址不变为何要 replace 才能命中真实路由。
6. 安全观澄清：前端权限是体验优化，真鉴权在接口。
7. **横向对比**：本项目双模式 vs Vue Router addRoute 范式 vs 纯后端下发全量结构；与第 03 课方法论闭环。

### 图表建议（Mermaid）

- `sequenceDiagram`：两种模式登录后的时序对比。
- `flowchart LR`：后端菜单树 → 组件映射 → 路由对象转换链。

### 演示要点（HTML 页规划）

- 双模式时序对比图。
- patchRoutes 注入示意。
- 安全边界澄清卡片。
- 结论页：模式选型看团队分工，安全边界必须清楚。

### AI 协作点

- 人：模式选择与组件映射契约。AI：生成器与映射表。
- 审查清单：嵌套层级是否遗漏？注入后是否记得 replace 重匹配？

## 第 14 课 · 路由守卫状态机：AuthGuard 的顺序设计与防闪烁

### 学习目标

1. 把 auth-guard.tsx 当显式状态机读懂。
2. 理解守卫为何用组件而非 loader。
3. 掌握弱网防闪烁细节。

### 核心问题

- 一次导航经过多少判断分支？顺序为何不可随意调整？
- 数据路由有 loader，为何权限逻辑反而放组件里？
- 弱网下 404/403 一闪而过的根因与治法？

### 内容大纲

1. 状态机全分支按序讲解：白名单 → 未登录分流 → 已登录访问 login → 拉用户信息+路由 → 等待态 null → 根路径跳首页 → 角色校验（公开/404/403）。
2. **横向对比三种守卫位置**：路由 loader（数据预取强、拿 UI 状态弱）vs 渲染期组件守卫（本项目，可读 hooks/可阻断渲染）vs 框架中间件（RR7 Framework/Edge Middleware，适合 SSR）。
3. 防闪烁：setupLoading/hideLoading、replace+flushSync、等待态统一 null。
4. 失败处理：allSettled + 非 401 跳 500。
5. 9 种导航场景验证清单。

- `stateDiagram-v2`：守卫状态机全图。
- `sequenceDiagram`：弱网刷新时的渲染时间轴（处理前后对比）。

## 第 15 课 · 多标签页与 KeepAlive：缓存生命周期设计

### 学习目标

1. 理解多标签的产品价值与状态复杂度。
2. 读懂 tabs store：增删、关闭策略、拖拽、持久化。
3. 理解 KeepAlive 缓存生命周期与标签/登录态的联动。

### 核心问题

- 多标签状态本质存的是什么？
- React 没有 KeepAlive，缓存靠什么？何时销毁？
- 关闭标签、退出登录、刷新按钮分别怎样作用于缓存？

### 内容大纲

1. tabs 数据模型：Map 存 openTabs、activeKey、刷新/最大化标记、historyState。
2. 操作全集：新增/激活/五种关闭/dnd-kit 拖拽/右键菜单。
3. **纵向 + 横向选型**：
   - 纵向：早期 hack 隐藏 DOM → react-activation（劫持卸载）→ keepalive-for-react（基于 React 能力的缓存容器）；
   - 横向：keepalive-for-react vs react-activation vs 自研；维护活跃度与 React 19 兼容性为关键依据。
4. container-layout 按 openTabs 决定缓存集合；meta.keepAlive 与标签开关；最大化/刷新即主动失效。
5. 生命周期联动：退出登录 resetTabs + access 重置 → 缓存清空；登录后持久化恢复与动态路由先后。

- `flowchart TD`：标签动作 → store → 缓存动作映射。

- 结论页：缓存是需要被状态机管理的资源。
